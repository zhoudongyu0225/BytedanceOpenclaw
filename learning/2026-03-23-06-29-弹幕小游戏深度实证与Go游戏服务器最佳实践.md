### 1.2 zmgr_logic.go WebSocket核心架构

**连接结构体 `WebsocketAnchorClient`**：
- `Socket *websocket.Conn` - WebSocket连接
- `Send chan []byte` - 发送管道（容量10000）
- `BarrageMessageChan chan *pb.MessageList` - 弹幕消息管道（容量10000）
- `LikeMessageList *pb.MessageList` - 点赞合并队列
- `PlayerMap sync.Map` - 玩家Map
- `AnchorV *pb.AnchorDBInfo` - 主播数据

**数据包格式**（WsSend方法）：
```
[4字节body长度] + [2字节command] + [1字节加密标志] + [1字节压缩标志] + [body]
```
- body > 100字节时自动Gzip压缩（判断依据：压缩后更小才发压缩版）
- 加密标志固定为false（未使用加密）
- 压缩标志：true=Gzip压缩，false=原始

**Read协程处理流程**：
1. 每秒触发 ticker1 → 调用 `ws.SlgTimeTick()` + `LikeMessage(ws.LikeMessageList, ws)`
2. 每3600秒触发 ticker3600（当前为空实现）
3. 从 `wbMessageModelChan` 接收业务消息
4. 从 `ws.BarrageMessageChan` 接收弹幕消息 → 调用 `convergeMessage`

**Write协程**：
- 从 `ws.Send` 管道读取消息
- 超时写关闭时间：`common.WsWriteOut` 秒
- 超时关闭连接

**convergeMessage 消息分发**：
- "GiftMessage" → GiftMessage()
- "ChatMessage" → ChatMessage()
- "LikeMessage" → 合并到 `ws.LikeMessageList`（按Uid累加Count）

**点赞合并逻辑**（mergeMessagesLike）：
```go
// 按Uid分组，相同Uid的Count数值累加
mergedMessages[uid].Count = fmt.Sprintf("%v", a+b)
```

## 二、Go游戏服务器最佳实践（实证分析）

### 2.1 当前架构优点

1. **双协程读写分离**：Read/Write各占一个协程，通过Channel解耦，避免了单个锁的竞争
2. **消息合并机制**：LikeMessage按Uid合并，避免高频点赞刷屏
3. **分层超时设计**：Read超时动态（登录前20秒，登录后20秒），Write超时固定
4. **优雅关闭**：先关闭Read→再关闭Write→最后Close Socket，有10ms缓冲
5. **自动压缩**：>100字节时比较压缩前后大小，只在有效时压缩
6. **房间级隔离**：通过RoomIdAccontIdMap实现房间到主播的映射

### 2.2 潜在改进点识别

**改进1：panic恢复包裹粒度**
```go
// 当前：每个协程有一个大的defer recover
go func() {
    defer func() {
        if err := recover(); err != nil {
            stack := debug.Stack()
            untils.PanicPoss1(err, stack, ws.AccountId)
        }
    }()
    // 所有逻辑混在一起
}()

// 建议：关键操作单独recover，避免单个消息处理panic杀死整个协程
```

**改进2：PlayerRoomIdMap使用sync.Map替代map+mutex**
```go

// 建议：sync.Map更适合「写入后长期读取」模式
```

```go
// BarrageMessageChan混合了：弹幕、礼物、点赞
```

- `iter` 包正式稳定（RangeFunc）—— 可实现自定义迭代器
- `unique` 包稳定（ deduplicate反射替代）

- `go mod tidy -e` 新增 `-excludes` flag
- `go test -shuffle` 随机测试顺序
- `debug.BuildInfo` 改进
- 性能改进：GC pause < 1ms司空见惯

### 4.2 潜在安全风险

**风险1：CheckOrigin过于宽松**
```go
// 当前代码
CheckOrigin: func(r *http.Request) bool {
    return true  // 接受所有来源
},

// 建议：验证origin
CheckOrigin: func(r *http.Request) bool {
    origin := r.Header.Get("Origin")
    allowedOrigins := map[string]bool{
        "https://yourgame.com": true,
        "https://admin.yourgame.com": true,
    }
    return allowedOrigins[origin]
},
```

**风险2：消息大小未限制**
```go
// 当前：未限制单条消息大小
// 建议：解析前检查数据长度
if len(data) > 1024*1024 { // 1MB上限
    return
}
```

**风险3：心跳未强制验证**
```go
// 当前：PingPong更新LastPingTime但未主动踢出超时
// 建议：后台协程定期检查，超时30秒未Ping则关闭
```

**风险4：积分操作非原子性**
```go
// 当前：读出积分→计算→写入，三步非原子
score := model.GetGameWeekRankByRankVo(...)
pdb.Score = currWeekScore
model.UpdateGameWeekRank(...) // 异步写入

// 建议：使用Lua脚本保证原子性
```
