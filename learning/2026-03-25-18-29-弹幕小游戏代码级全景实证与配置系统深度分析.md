### 2.2 双协程架构（Read/Write完全分离）

```

                    │              Read() 协程                    │
                    │  ┌─────────────────────────────────────┐  │

                    │  │   ↓ BinaryFrame                    │  │
                    │  │ wbMessageModel.Read(dataBuffer)     │  │
                    │  │   ↓                                 │  │
                    │  │ wbMessageModelChan ←─────────────┐  │  │
                    │  └─────────────────────────────────────┘  │
                    │                   ↓                      │
                    │  ┌─────────────────────────────────────┐  │
                    │  │ 主播协程（for/select + 3个ticker）   │  │
                    │  │   - 1秒 ticker: SlgTimeTick+LikeMsg │  │
                    │  │   - 3600秒 ticker: 跨天检查         │  │
                    │  │   - wbMessageModelChan: 登录/心跳   │  │
                    │  │   - BarrageMessageChan: 弹幕消息     │  │
                    │  └─────────────────────────────────────┘  │
                    │           ↓                               │
                    │  ┌─────────────────────────────────────┐  │
                    │  │ convergeMessage()                    │  │
                    │  │   GiftMessage() ← 直接处理           │  │
                    │  │   ChatMessage() ← 直接处理           │  │

                    │  └─────────────────────────────────────┘  │
                    └─────────────────────────────────────────────┘

                    ┌─────────────────────────────────────────────┐
                    │              Write() 协程                     │
                    │  for {                                        │
                    │    msg ← ws.Send  (阻塞等待)                   │
                    │    ws.Socket.WriteMessage(BinaryMessage, msg) │
                    │  }                                            │
                    └─────────────────────────────────────────────┘
```

**关键发现：LikeMessage vs GiftMessage vs ChatMessage 处理模型不同！**

| 消息类型 | 触发方式 | 处理时机 | 合并机制 |
|---------|---------|---------|---------|
| GiftMessage | convergeMessage直接调用 | 每次Webhook来立即处理 | 无合并 |
| ChatMessage | convergeMessage直接调用 | 每次Webhook来立即处理 | 无合并 |
| LikeMessage | ticker 1秒定时调用 | 每秒批量处理 | 10秒滑动窗口合并到LikeMessageList |

### 2.4 定时器Tick机制（Read协程内的for/select）

```go
ticker1 := time.NewTicker(time.Second * 1)      // 1秒 ticker
ticker3600 := time.NewTicker(time.Second * 3600) // 1小时 ticker

for {
    select {
    case <-ticker3600.C: // 1小时（未使用）
    case <-ticker1.C:   // ← 每秒执行
        ws.SlgTimeTick()       // 游戏逻辑tick
        LikeMessage(ws.LikeMessageList, ws)  // 批量处理点赞（关键！）
        ws.LikeMessageList = &pb.MessageList{}  // 清空合并队列
    case wbMessageModel := <-wbMessageModelChan:
        // 登录/心跳等控制消息
    case msg := <-ws.BarrageMessageChan:
        ws.convergeMessage(msg)  // 弹幕/礼物/点赞消息
    }
}
```

**关键观察：**
- 每秒清空`LikeMessageList`，然后调用`LikeMessage`处理
- LikeMessage的"冷却"实际上由ticker的1秒间隔保证
- **GiftMessage和ChatMessage没有ticker限流，每次Webhook都立即处理**
- 存在`//todo:跨天`注释，说明跨天处理逻辑未完整实现

## 三、关键Bug与安全隐患（新发现！）

### 3.1 🔴 P0严重：敏感词过滤器Nil Pointer Panic

```go
// sensitive.go
func GetSensitiveFilter() *SensitiveFilter {
    if sensitiveFilter == nil {
        sensitiveFilter, _ = NewSensitiveFilter("./mgc.txt")  // 错误被丢弃！
    }
    return sensitiveFilter  // 可能返回nil
}

func (sf *SensitiveFilter) ContainsSensitiveWord(text string) bool {
    return sf.filter.Filter(text) != text  // ← sf为nil时panic！
}
```

**风险链：**
1. `NewSensitiveFilter` 返回error（文件不存在、权限问题、DFA初始化失败）
2. `sensitiveFilter, _ = ...` error被`_`丢弃
3. `GetSensitiveFilter()` 返回nil
4. 调用`ContainsSensitiveWord()` → `sf.filter.Filter()` → **nil pointer dereference → panic**

**mgc.txt路径风险：**
- 路径`./mgc.txt`是**相对路径**，相对于进程**运行时工作目录**，不是源代码目录
- Docker部署时工作目录通常是`/app`或`/`, 而非`$WORKDIR/commonDmGameServer/`
- mgc.txt实际存在于源代码目录：`/root/.openclaw/workspace/commonDmGameServer/commonDmGameServer/mgc.txt`
- **容器内若工作目录不对，文件找不到**

**建议修复：**
```go
func GetSensitiveFilter() *SensitiveFilter {
    if sensitiveFilter == nil {
        sf, err := NewSensitiveFilter("./mgc.txt")
        if err != nil {
            zlog.Logger.Warn().Msgf("敏感词过滤器初始化失败，降级无过滤: %v", err)
            // 降级：创建空过滤器避免panic
            fallback := &SensitiveFilter{
                filter: sensitive.New(),
            }
            sensitiveFilter = fallback
        } else {
            sensitiveFilter = sf
        }
    }
    return sensitiveFilter
}

func (sf *SensitiveFilter) ContainsSensitiveWord(text string) bool {
    if sf == nil || sf.filter == nil {
        return false  // 安全降级
    }
    return sf.filter.Filter(text) != text
}
```

## 九、代码质量综合评估（2026-03-25晚间更新）

### 9.1 架构优点
1. **双协程WebSocket**：读写分离，逻辑清晰
2. **Gzip压缩**：自动判断压缩收益（100字节门槛）
3. **点赞合并机制**：减少客户端渲染压力
4. **Redis ZSet排行榜**：高效的实时排名
5. **MongoDB主播数据**：完整的主播信息管理
6. **Panic恢复**：所有协程都有recover，防止整体崩溃

### 9.2 技术债与风险点
