## 四、知识巩固：关键理解点

### 4.1 消息合并机制（LikeMessageList）

```go
// 10秒滑动窗口合并机制
// 1. 收到LikeMessage：LikeMessageList合并
// 2. 每1秒ticker：处理LikeMessageList并清空
// 3. 新消息加入已存在的消息（复用已有MessageList）
```

**为什么ChatMessage/GiftMessage不需要合并？**
- ChatMessage是文本弹幕，需要实时性
- GiftMessage包含具体礼物信息，不能合并
- LikeMessage是计数型消息，可以批量处理

### 4.2 WebSocket数据包处理流程

```
抖音Webhook → HTTP回调 → zbarrage_mgr.go路由
→ zmgr_logic.go.Read() 协程读取
→ gob反序列化 → wbMessageModelChan
→ 主播协程BarrageMessageChan接收
→ convergeMessage() 分发
→ GiftMessage()/ChatMessage() 直接处理
→ LikeMessage() → LikeMessageList合并
→ ws.Send → Write()协程发送
```

3. **泛型类型别名**：更简洁的泛型实现
