## 五、WebSocket高并发弹幕技术方案

### 5.1 弹幕WebSocket技术选型

结合实时对战、高并发、包体敏感的需求，**原生WebSocket + Protobuf**是最优方案：

**核心优势：**
- **性能可控**：原生WebSocket最底层，无额外开销
- **Protobuf压缩**：极大压缩消息体积，减少网络传输时间
- **灵活性高**：所有逻辑（重连、心跳、分片）均可自行定制
- **包体友好**：相比Socket.IO，引入开销更小

### 5.2 弹幕协议设计要点

**粘包/半包问题：**
- TCP缓冲区可能将多次小数据包合并（粘包）
- 或将大数据包拆分成多个（半包）
- 解决方案：消息协议设计时需包含长度字段或分隔符

**协议设计建议：**
```protobuf
// Protobuf消息示例
message DanmakuMessage {
    required int64 timestamp = 1;
    required string user_id = 2;
    required string content = 3;
    optional int32 color = 4;
    optional string position = 5; // roll/float/top/bottom
}
```

### 5.3 高并发优化方案

**Linux文件描述符限制：**
- 每个WebSocket连接占用1个fd
- Linux默认单进程fd上限为1024
- 需要通过ulimit或内核参数调整

**Node.js性能数据：**
- 32GB内存可支持**2200并发连接**（WebSocket场景）

**广播消息内存泄漏风险：**
- 大型多人在线游戏中，全服公告、玩家状态更新等广播消息
- 需要实现消息生命周期管理和合理的缓存淘汰策略

**优化策略总结：**
| 优化维度 | 技术方案 |
|----------|----------|
| 并发连接数 | fd管理、ulimit调整、连接池 |
| 消息体积 | Protobuf压缩、消息分片 |
| 写入性能 | 事务批处理、异步写入、写入缓存 |
| 性能瓶颈 | 数据库写入节点、负载均衡器、CDN缓存节点 |
| 连接稳定性 | 心跳包保活、状态机监控连接状态 |
